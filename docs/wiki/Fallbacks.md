# Fallbacks

Problems in the configuration never stop OpenCode. A missing or unparsable `models.jsonc`, an invalid entry or a ref that resolves nowhere leaves the affected agents as OpenCode would configure them; invalid entries are skipped one by one, so the rest of the file still applies. An invalid [model setting](Usage#model-settings) is left out on its own, and its ref still applies. An undefined profile is skipped as [Profiles](Profiles#precedence) describes.

A ref whose model no connected provider offers falls back too, to the model OpenCode would use without the ref: the agent's own `model`, a subagent's parent model, else OpenCode's default. The plugin applies refs before OpenCode loads providers, so it saves which models were available in OpenCode's state directory and leaves unavailable refs out from the next start. It saves them separately for each provider setup (the `provider` config, the providers `auth.json` holds credentials for, and which of the environment variables providers connect with are set, as OpenCode's cached models.dev catalog lists them), so processes started from different environments on one project don't undo each other's. The eight most recently used setups are kept per project. Until it has checked once, prompts to such a model are moved to the fallback, with the agent's own `temperature` and `top_p` but still the ref's `options` until the reload leaves the ref out, and once no session is busy and no terminal is open the plugin reloads the project, which restarts its MCP and LSP servers. It tries again whenever a session goes idle or a terminal exits or closes, shows a warning toast while an open terminal holds the reload back, and stops after three reloads OpenCode refuses. That covers built-in agents such as `compaction` and `title` that never receive a prompt of their own; in the first process that meets a broken ref they, and commands that name the agent, can still fail until that reload. A prompt that reuses a ref's unavailable model after the ref is fixed falls back too, while a model you set yourself, on an agent without a ref or as the top-level `model`, is left as OpenCode would use it, even one a ref used before. If a provider connects after the last check, its refs apply again after the first reload.

The TUI shows a warning toast with the first new problem and how many more there are. A problem is toasted once per OpenCode launch, and again after it changes; `/model-config` lists all current ones. The server plugin also toasts a prompt that runs on another model because of a ref, once per OpenCode process, so clients without the TUI plugin that show OpenCode's toasts see it too. It is also logged as a warning, the only trace in `opencode run` (see `--print-logs`).
